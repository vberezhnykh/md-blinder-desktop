# MD Blinder Desktop

Настольная программа для Windows (Python + PySide6): DOCX, XLSX и PDF (включая сканы) в Markdown и обезличивание. Браузерная версия живет в репозитории md-blinder и больше не развивается; правки делаются только здесь.

## Команды

```bash
python -m pip install -e ".[dev]"
python scripts/fetch_ocr_models.py      # модели Indra OCR (~25 МБ), нужны тестам OCR
QT_QPA_PLATFORM=offscreen python -m pytest -q
ruff check src tests scripts
```

Версии всех зависимостей закреплены в `uv.lock`, CI и `build.bat` ставят ровно их. После правки зависимостей в `pyproject.toml` выполнить `uv lock` (обновить все версии — `uv lock --upgrade`, отдельным PR) и закоммитить `uv.lock`. Обычный onnxruntime на Windows не ставится: его заменяет onnxruntime-directml (см. `[tool.uv]` в `pyproject.toml`).

В Linux-контейнере для Qt нужны системные библиотеки: `apt-get install -y libegl1 libgl1 libxkbcommon0 libfontconfig1 libdbus-1-3`. CI работает на Python 3.14; на других версиях отдельные тесты могут вести себя иначе из-за версий библиотек.

Тесты с настоящей моделью NER (`pytest.mark.model`) пропускаются, если модели нет в каталоге данных (`MD_BLINDER_DATA_DIR`). Модель GLiNER (~580 МБ) скачивается с Hugging Face:

```bash
MD_BLINDER_DATA_DIR=<папка> python -c "from md_blinder.components import model_asset; model_asset.download_model()"
```

## Релиз

Любая заметная пользователю правка выходит релизом в том же PR: поднять `__version__` в `src/md_blinder/__init__.py` и добавить раздел `## <версия>` в начало CHANGELOG.md (тест падает без раздела). После слияния в main CI публикует релиз `desktop-v<версия>`, если его еще нет. Если PR слит поверх того же main, на котором прошли его проверки (дерево файлов совпадает), прогон main берет проверенную сборку из PR, и релиз выходит примерно через минуту; иначе тесты и сборка идут заново (около 4 минут). Проверять выход релиза через 2 минуты после слияния, а если прогон main пошел заново, еще через 4, а не через 10–15. Перед подъемом версии посмотреть последний тег и открытые PR: параллельный PR мог занять номер. Тексты CHANGELOG пишутся для пользователя, без названий функций и файлов.

## Тестовый корпус

Корпус реальных договоров конфиденциален: в репозиторий, CI, комментарии и PR не попадают ни файлы, ни значения из них. Наружу выносятся только сводные метрики. Прогон:

```bash
python scripts/eval_corpus.py <папка test-samples> --cache <папка кеша>
```

Скрипт кеширует конвертацию и ответ модели NER, поэтому правки фильтра, правил, склейки и поиска повторов проверяются за секунды. Любую правку качества находок сравнивать с прогоном до нее: полнота не должна упасть, шум и кандидаты не должны вырасти без причины.

## Устройство

- `convert/` — DOCX (mammoth), XLSX (openpyxl), PDF (PyMuPDF, таблицы через pymupdf-layout), OCR сканов (Indra OCR, `ocr.py`, `script_mix.py`).
- `anonymize/` — правила (`regex_detectors.py`, шаблоны с семантикой JS через `_js_regex.py`), фильтр находок модели (`ner_filter.py`), склейка, поиск повторов (`related.py`), пакет документов (`batch.py`), обезличенный PDF (`redacted_pdf.py`).
- `ner/` — сессия ONNX Runtime для GLiNER: CPU или DirectML на Windows, калибровка, батчи. Одна модель на программу, ее скачивание, предзагрузка и состояние для индикатора стартового экрана — `model_holder.py`.
- `ui/` — интерфейс, `jobs.py` — фоновая обработка, `storage/` — история в SQLite.

Картинки из DOCX приходят как data URI в сотни тысяч символов и перед поиском маскируются пробелами той же длины. Поэтому в шаблонах поиска нельзя ставить неограниченный повторитель пробелов между обязательными частями: на такой строке перебор становится квадратичным.

## Стиль

Комментарии, сообщения коммитов, PR и тексты интерфейса — на русском. Строки до 120 символов.
