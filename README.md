# MD Blinder Desktop

Настольная версия MD Blinder для Windows на Python и PySide6. Делает то же, что браузерная: конвертирует DOCX, XLSX и PDF (включая сканы) в Markdown, находит персональные данные регулярными правилами и моделью GLiNER, дает проверить кандидатов и выгрузить обезличенный текст. Документы обрабатываются на компьютере и никуда не отправляются.

Несколько файлов, выбранных или перетащенных вместе, обрабатываются как пакет: одно и то же значение получает одинаковую метку во всех документах пакета. Например, в договорах «Альфа — Бета» и «Бета — Гамма» «Бета» везде заменяется одной меткой. Значения, подтвержденные в одном документе, размечаются и в остальных, даже если модель их там не нашла. В меню «Пакет» можно открыть другие документы пакета, добавить новые и выгрузить весь пакет одним .md (под заголовками «Документ 1», «Документ 2», без имен файлов) и общей таблицей замен. Пакет совместим с браузерной версией через экспорт и импорт истории.

Таблицы Excel (.xlsx) читаются только настольной версией. Каждый лист становится разделом `## <имя листа>` с таблицей Markdown; пустые строки и столбцы пропускаются, объединенные ячейки оставляют значение в первой ячейке. Для формул берется сохраненное значение, то есть то, что видно в Excel; книгу, которую сгенерировала программа без пересчета, стоит один раз открыть и сохранить в Excel. Скрытые листы выгружаются с пометкой «скрытый лист». Старый формат .xls и книги с паролем не поддерживаются. В экспорте истории у таких документов формат `xlsx`; браузерная версия при импорте показывает их как docx, текст и находки переносятся без изменений.

Браузерная версия живет в репозитории [md-blinder](https://github.com/vberezhnykh/md-blinder). До версии 0.2.4 настольная программа выпускалась там же.

## Что скачивается и куда

Сборка не содержит тяжелых файлов. Программа спрашивает, прежде чем что-то скачать:

- модель распознавания имен GLiNER (`onnx-community/gliner_multi-v2.1`, fp16, около 580 МБ) — при первом распознавании; если Hugging Face закрыт в сети, можно указать заранее скачанный `model_fp16.onnx`;
- модель распознавания текста Indra OCR (`datalab-to/indra-ocr`, около 25 МБ) — при первом PDF-скане. Скачиваются только модели для латиницы и кириллицы. Распознавание идет на процессоре, около секунды на страницу; таблицы на сканах переводятся в таблицы Markdown.

Версии, размеры и контрольные суммы закреплены. Данные лежат в `%LOCALAPPDATA%\md-blinder`: `models\` и `history.sqlite`. Путь можно поменять переменной `MD_BLINDER_DATA_DIR`.

История хранит исходный текст и найденные значения без шифрования, как и браузерная версия. Экспорт истории в JSON совместим с браузерной версией в обе стороны.

## Сборка на Windows

Нужен Python 3.14: для onnxruntime пока нет сборок под 3.15. Права администратора не требуются.

```bat
py install 3.14
build.bat
```

`build.bat` создает `.venv`, ставит зависимости, прогоняет тесты и собирает папку `dist\MD Blinder` с `MD Blinder.exe` (около 400 МБ без модели). Папку можно скопировать куда угодно целиком. Для запуска из исходников без сборки есть `run.bat`.

`"MD Blinder.exe" --self-check` проверяет собранную программу без окна: зависимости, OCR и калибровку модели NER, если они скачаны. Отчет пишется в `%LOCALAPPDATA%\md-blinder\self-check.txt`.

Готовую сборку под Windows также выкладывает CI (workflow Desktop, артефакт `md-blinder-windows`). Файлы, скачанные из интернета, Windows помечает, и SmartScreen может предупредить при первом запуске; сборка на своем компьютере этого избегает.

## Обновление

Программа при запуске проверяет релизы `desktop-v*` в репозитории на GitHub: это один запрос за номером последней версии, документы и история не отправляются. Если есть новая версия, сверху появляется плашка «Обновить». Программа скачивает архив с проверкой SHA-256, закрывается, заменяет `MD Blinder.exe` и папку `_internal` и запускается снова. Модели и история лежат в каталоге данных и не затрагиваются. Проверку при запуске можно выключить внизу стартового экрана, там же кнопка «Проверить обновления».

Новая версия выпускается подъемом `__version__` в `src/md_blinder/__init__.py` вместе с разделом этой версии в [CHANGELOG.md](CHANGELOG.md): после пуша в main workflow «Desktop» прогонит тесты, соберет программу, проверит ее `--self-check` и, если релиза `desktop-v<версия>` еще нет, опубликует его с архивом `md-blinder-windows.zip` и контрольной суммой. Описание релиза берется из раздела версии в CHANGELOG.md; тест не даст поднять версию без этого раздела.

## Меню проводника

Собранная программа при запуске добавляет в меню файлов .docx, .xlsx и .pdf пункт «Анонимизировать в MD Blinder»: щелчок правой кнопкой мыши открывает файл в программе. Пункт прописывается в реестре текущего пользователя (`HKCU\Software\Classes\SystemFileAssociations`), права администратора не нужны, ассоциации файлов с Word, Excel и просмотрщиком PDF не меняются. После переноса папки программы путь обновится при следующем запуске. В Windows 11 пункт находится в разделе «Показать дополнительные параметры» (Shift+F10): в сокращенное меню попадают только программы, установленные пакетом MSIX. Пункт выключается флажком «Пункт в меню проводника» внизу стартового экрана.

Если программа уже открыта, файл открывается в ее окне, второй экземпляр не запускается: два окна писали бы в одну историю. Пока идет обработка другого файла, программа просит открыть новый после ее окончания.

## Разработка

```bash
py -3.14 -m venv .venv          # или python3.14 -m venv .venv
.venv/Scripts/python -m pip install -e ".[dev]"
.venv/Scripts/python -m pytest -q
.venv/Scripts/python -m md_blinder
```

Тесты с моделями запускаются, если файлы есть: модели ищутся в каталоге данных (`MD_BLINDER_DATA_DIR`), модели OCR можно указать отдельно папкой `MD_BLINDER_OCR_MODELS`. `python scripts/fetch_ocr_models.py` скачивает модели OCR в каталог данных; CI делает это перед тестами.

Лицензия весов Indra OCR — OpenRAIL-M с ограничениями: бесплатно для личного использования, исследований и компаний с выручкой или финансированием меньше $20 млн, нельзя конкурировать с API Datalab. Файл `LICENSE` скачивается вместе с моделями.

Код повторяет модули браузерной версии один к одному, с теми же порогами и правилами; TS-тесты перенесены в `tests/`. Отличия:

- смещения сущностей считаются в кодовых точках Python, а не в UTF-16; при импорте и экспорте истории они пересчитываются;
- PDF разбирается PyMuPDF вместо pdf.js, координаты переводятся в систему pdf.js, чтобы пороги остались прежними;
- таблицы в текстовом слое PDF ищет `page.find_tables` вместе с моделью разметки `pymupdf_layout` (модели ONNX около 50 МБ входят в сборку): находятся таблицы с рамками и часть таблиц без рамок, объединенные ячейки раскладываются как в DOCX, продолжение таблицы на следующей странице дописывается к ней. Если в ячейки таблицы не попало больше 2% символов из ее области, страница собирается обычным текстом. Поиск добавляет примерно 0,2–0,5 секунды на страницу. В сканах таблицы пока не ищутся;
- HTML из mammoth переводится в Markdown через markdownify с теми же правилами для таблиц, что у Turndown.

Интерфейс повторяет веб-версию: те же токены цветов (`src/index.css`), шрифты IBM Plex (OFL, лежат в `src/md_blinder/ui/assets/fonts`), значки и раскладка экранов. В редакторе есть номера строк, ручки изменения границ вхождения, подсветка при наведении в обе стороны и объединение замен прямо из текста.
